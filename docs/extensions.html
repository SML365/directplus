EXTENSIONS

Implementation Details: All Direct+ extensions are implemented in the language itself and can be used just like any other module.
MathUtils:
use(__mathutils)
Imports the MathUtils extension, for doing more advanced math operations.
run(/__mathutils:square[num] => destination)
Squares a number and stores the result in the specified destination.
run(/__mathutils:cube[num] => destination)
Cubes a number and stores the result in the specified destination.
run(/__mathutils:pow[num, pow] => destination)
Raises a number to the specified power.
run(/__mathutils:abs[num] => destination)
Returns the absolute value of a number.
run(/__mathutils:min[num1, num2] => destination)
Returns the smallest of the two numbers.
run(/__mathutils:max[num1, num2] => destination)
Returns the largest of the two numbers.
run(/__mathutils:round[num, place] => destination)
Rounds the input number to the selected decimal place. For example, [51.77, 1] returns 51.8.
run(/__mathutils:clamp[num, min, max] => destination)
Clamps the input number between the specified minimum and maximum values.
ListUtils:
use(__listutils)
Imports the ListUtils extension, which provides additional functions for working with lists.
run(/__listutils:sort[list] => destination)
Sorts the list literal and stores the result in the specified destination. Lists with numbers are sorted least => greatest and string lists are sorted alphabetically. For a list with mixed types, numbers always come before the strings.
run(/__listutils:count[list, element] => destination)
Counts the amount of instances of an element in the list and stores the result in the specified destination.
run(/__listutils:unique[list] => destination)
Returns a new list with all duplicate elements removed. (List order is mostly preserved)
run(/__listutils:reverse[list] => destination)
Returns the reversed value of the input list.
run(/__listutils:min[list] => destination)
Returns the smallest value in the input list.
run(/__listutils:max[list] => destination)
Returns the largest value in the input list.
StringUtils:
use(__stringutils)
Imports the StringUtils extension, which provides additional functions for working with strings.
run(/__stringutils:separate[str, delimiter] => destination)
Splits a string into a list of substrings based on the specified delimiter. Note: The delimiter has to be one single character.
run(/__stringutils:join[list, delimiter] => destination)
Joins a list of strings into a single string, using the specified delimiter.
run(/__stringutils:isempty[str] => destination)
Returns 'true' if a string is empty, and 'false' if not.
run(/__stringutils:tokenize[str, {list, of, character, groups}, characters_to_ignore] => destination)
Tokenizes the input string based on the list of character groups and the character ignore list. Example: running tokenize on ["hello123wor:ld5", {"abcdefg...xyz", "1234567890"}, ":"] will result in a output list of {"hello", "123", "world", "5"}.
GUIUtils:
use(__guiutils)
Imports the GUIUtils extension, which provides functions for animation and GUI utilities.
run(/__guiutils:ease[value, target, smoothness] => destination)
Eases a value towards a target value based on the specified smoothness factor. The higher the smoothness, the slower the easing.
Disk:
use(__disk)
Imports the Disk extension, which provides a virtual disk and filesystem.
run(/__disk:init)
Initializes the root folder. This must be run before any other disk commands.
run(/__disk:walk[{list, of, paths}])
Traverses the specified list of paths in the virtual filesystem. Relative paths are not supported (paths must be absolute but not include the root path). Ex: {documents, my_file}
run(/__disk:update[root\full\path, new_contents])
Updates an existing file or folder in the virtual filesystem. Use full paths: @__disk:root\documents\my_file
run(/__disk:folder[name, contents])
Creates a new folder in the virtual filesystem. Each folder is a Direct+ variable and its name is a full path, with entries separated by backslashes. Ex: @__disk:root\documents\my_folder, but this command uses relative paths. Ex: If you're in @__disk:root\documents, you can make 'my_folder'.
run(/__disk:file[name, contents])
Creates a new file in the virtual filesystem. Each file or folder is a Direct+ variable and its name is a full path, with entries separated by backslashes. Ex: @__disk:root\documents\my_file, but this command uses relative paths. Ex: If you're in @__disk:root\documents, you can make 'my_file'.
run(/__disk:delete[name])
Deletes an existing file or folder in the virtual filesystem. Uses relative paths. Ex: If you're in @__disk:root\documents, you can delete 'my_file'. Note that since Direct+ can't delete variables, only the reference to the variable is removed.
Installing Extensions:
Using Direct+'s built in extension manager, you can install extensions from the Direct+ server! Note that this technology is very new and not the most stable. All install extensions are prefixed with _, unlike built-in extensions, which are prefixed with __.
Supported Extensions
name          use case                               commands

_test         test if extension system works         /_test:test
Technical Stuff for Technical People:
Direct+'s extensions server is powered by ScratchAttach. Direct+'s packets use 2-integer encoding, meaning that for each character, two integers are used to represent it. For example, the character 'a' is represented as '11'. This is the same encoding that pressing [' + s / l] uses to save and load Direct+ files! Direct+ module installations only work in TurboWarp. The encoded packets are transferred at a speed of around 1 kilobyte per second, or around 500 bytes of unencoded text per second. They are transferred with a 1s delay enforced by the client, to prevent one client from using all the resources and triggering errors in other installations happening at the same once, though only one installation is happening most of the time. There are four installation buffers, meaning four parallel installations can happen at once (theoretically) and get reset once installation finishes. If something goes wrong, the state may not return to normal, so all variables are reset every few hours. If this reset happens during a download, it may cause a download failiure, which is safe but annoying. Reset times are not finalized yet and will be displayed here once finalized.
